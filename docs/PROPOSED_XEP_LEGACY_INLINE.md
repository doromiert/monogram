# Proposed XEP: authenticated inline emoji in Legacy OMEMO

Local proposal, version 0 (2026-11-14); not an assigned or accepted XEP.

XEP-0384 Legacy OMEMO authenticates only a UTF-8 body. XEP-0071 XHTML-IM
and XEP-0231 BoB outside that ciphertext cannot safely supply private artwork.
Modern OMEMO/SCE and Monocles OMEMO2 already carry those elements inside their
existing authenticated content; those wire formats do not change.

A client advertises `urn:monogram:legacy-inline:0` in XEP-0030 disco#info.
A sender queries the recipient's available full JID (bare JID if none is known).
Only a positive capability response enables this format. Other clients receive
the ordinary Unicode fallback. Existing own devices also need this decoder.
Group sending remains on the ordinary Legacy body profile.

The encrypted UTF-8 body begins with exactly
`urn:monogram:legacy-inline:0\n`, followed by a UTF-8 XML element:

```xml
<message xmlns="jabber:client">
  <body>🙂</body>
  <html xmlns="http://jabber.org/protocol/xhtml-im">
    <body xmlns="http://www.w3.org/1999/xhtml"><p><img src="cid:sha-256+HASH@bob.xmpp.org" alt="🙂" width="20" height="20"/></p></body>
  </html>
  <data xmlns="urn:xmpp:bob" cid="sha-256+HASH@bob.xmpp.org" type="image/png">BASE64</data>
</message>
```

The container has no attributes, exactly one client body, and only body,
XHTML-IM html, and BoB data children. Routing, identity, stanza IDs and displayed
markers continue to come from the existing authenticated sender/journal and
outer stanza rules. No custom artwork is copied outside the encryption.

The complete plaintext is limited to 256 KiB. DTDs and declarations beginning
with `<!` are rejected. Existing inline validation requires exact fallback-body
agreement, nonoverlapping code-point ranges, SHA-256 content IDs, supported
media types, at most 64 ranges/16 assets/128 KiB of asset bytes, and bounded XHTML
depth/node counts. No external image URLs or network fetches are allowed.
Malformed prefixed content is rejected; it cannot override routing or actions.

Both clients decode only after successful Legacy authentication and retain the
existing durable journal and trust checks. Explicitly blocked devices remain
blocked. Capability discovery runs on the sending worker. Artwork decode runs
off the UI thread; a discarded timeline row releases its renderer.

`tests/fixtures/legacy-inline/mobile.txt` is generated by the Android core
encoder and decoded by the Rust tests. Tests also cover real Legacy encryption,
no artwork on the public envelope, tampered hashes, plain-body compatibility,
and desktop asynchronous image loading through the production renderer.
