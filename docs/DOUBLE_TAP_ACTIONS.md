# Configurable message double taps

Settings → Stickers and Emoji → Double-tap actions contains separate incoming-message and own-message choices. Both default to the existing quick reaction. The reaction emoji still uses Telegram's native Quick Reactions screen. Choices are local to each Monogram account and persist across restarts.

Actions follow the supplied Exteragram APK: Disable, Reactions, Reply, Copy, Forward, Save, Repeat message, Delete, Translate message, and Edit for own messages. Save forwards to the account's Saved Messages; Repeat uses the existing forwarding path with the sender attribution removed. They run only in contexts that permit forwarding; Repeat also requires a writable destination. Delete retains the native confirmation dialog. Reply, copy, forward, edit and translate use the existing message-action handlers and menu eligibility, including media/caption and forwarding restrictions. Unavailable gestures are ignored.

The reference APK is `~/extera/exteraGram-full-universal-20261004.apk`, SHA-256 `1ed01526c0cb57bc798c29cc06ab4d01d30282ce2cc1b177f0222e906c22581f`. Static SDK DEX inspection and focused JADX output identified `com.exteragram.messenger.utils.chats.DoubleTapUtils` in classes4.dex and `org.telegram.ui.ChatActivity$12` in classes6.dex. Exteragram has separate incoming/outgoing settings and routes non-reaction gestures through its message action dispatcher. Incoming choices omit Edit; Monogram stores stable action IDs rather than the different incoming/outgoing menu indices.

This is an adaptation to Monogram's current Telegram UI and XMPP-compatible handlers. Exteragram's Telegram-only networking, feed routes and private helper classes are not imported. JADX reported errors in unrelated large methods; the recovered helper, double-tap listener, availability and dispatch methods were readable, and their action IDs were checked against DEX disassembly. These are static findings, not runtime Exteragram observations. REA registration was unavailable in the active session and was left unchanged; findings come from SDK/JADX, not REA Evidence.

A focused Robolectric check covers independent direction choices, preference reuse, invalid incoming Edit rejection and corrupt-value fallback. Real-phone gesture, saved/repeated-message delivery and permission behavior require separate validation; the agent does not send real-contact test messages.
